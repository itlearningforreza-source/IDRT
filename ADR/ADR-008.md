# ADR-008: Database: Migrations, Partitioning, Read Replicas

**Status:** Accepted
**Date:** 2026-11-18
**Deciders:** Principal Architect, Senior Blockchain Engineer, Financial Systems Architect
**Technical Story:** ADR-008

## Context

alembic in requirements but no migrations, config, or history. No partitioning strategy for high-volume tables (events, audit logs). No read replicas for analytics/dashboard queries.

## Decision

1) Initialize alembic with baseline migration from current schema. 2) All schema changes via migrations (CI enforced). 3) Partition token_events, reserve_events, bridge_events, audit_logs by month (pg_partman). 4) Deploy PostgreSQL primary + 2 read replicas (streaming replication). 5) Route analytics/dashboard queries to replicas. 6) Connection pooling via PgBouncer (primary: 20, replicas: 50). 7) PITR with WAL-G for point-in-time recovery. 8) Backup verification monthly.

## Consequences

### Positive
- Schema version control
- Query performance
- HA for reads
- Disaster recovery
- Audit compliance

### Negative
- Operational complexity
- Replication lag for reads
- Partition maintenance
- Cost for replicas
