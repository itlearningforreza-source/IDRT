# ADR-005: Upgrade Governance: TimelockController + Role Separation

**Status:** Accepted
**Date:** 2026-11-18
**Deciders:** Principal Architect, Senior Blockchain Engineer, Financial Systems Architect
**Technical Story:** ADR-005

## Context

Current upgrade uses UUPSProxy with _authorizeUpgrade checking only UPGRADER_ROLE. Multisig holds ALL roles (DEFAULT_ADMIN, MINTER, BURNER, PAUSER, UPGRADER, BLACKLISTER). No timelock enforced in code (only in config). No role separation.

## Decision

1) Deploy OpenZeppelin TimelockController with 48h delay for upgrades, 24h for role changes, 0h for emergency pause/blacklist. 2) Separate roles: Multisig = DEFAULT_ADMIN only. Security Council (separate multisig) = PAUSER, BLACKLISTER. Treasury Council = MINTER, BURNER. Upgrader = TimelockController only. 3) Grant UPGRADER_ROLE to TimelockController, not multisig directly. 4) All sensitive operations go through timelock queue→execute. 5) Emergency pause via Security Council (immediate).

## Consequences

### Positive
- Defense in depth
- Time for detection/response
- Role separation
- Audit trail
- Regulatory aligned

### Negative
- Operational complexity
- 48h delay for upgrades
- Multiple multisigs to manage
- Emergency procedures needed
