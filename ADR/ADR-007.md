# ADR-007: Compliance: Build vs Buy KYC/AML

**Status:** Proposed
**Date:** 2026-11-18
**Deciders:** Principal Architect, Senior Blockchain Engineer, Financial Systems Architect
**Technical Story:** ADR-007

## Context

Current KYC/AML is entirely mock (NotImplementedError for production). Need real eKYC, sanctions screening, transaction monitoring, SAR generation. Building in-house requires significant regulatory expertise and ongoing maintenance.

## Decision

Buy core compliance services, build orchestration: 1) eKYC: Onfido/Jumio/Sumsub (Indonesian KTP support required) 2) Sanctions: Chainalysis/TRM/ComplyAdvantage (real-time + batch) 3) Transaction Monitoring: Build rule engine (threshold, velocity, geography) + integrate provider alerts 4) SAR: Build template generator using provider data 5) PII Encryption: Application-level (pgcrypto) + Vault for keys 6) Data Retention: Automated per UU PDP (Indonesian Data Protection Law) 7) Compliance Orchestrator: Our service coordinating providers, managing tiers, generating audit trail

## Consequences

### Positive
- Faster time-to-market
- Regulatory expertise from vendors
- Ongoing updates handled
- Focus on business logic

### Negative
- Vendor lock-in
- Cost (per-check fees)
- Data sharing agreements
- Integration complexity
- Latency for real-time checks

## Alternatives Considered
- Full build (high effort, full control)
- Hybrid: buy screening, build monitoring
